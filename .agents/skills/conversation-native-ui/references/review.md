# Interface quality review

Review in this order:

1. **Job fit** — can the user identify the actual decision and next action quickly?
2. **Evidence identity** — are illustrative, computed, inferred, reported and observed sources distinguishable?
3. **Boundary** — what context qualifies this judgment? What is unknown?
4. **Authority** — are approval, execution and outcome separate and honestly labeled?
5. **Interaction economy** — is the inline surface compact; are controls visible and functional?
6. **Accessibility** — keyboard focus, labels, readable contrast, at least 44px touch targets where possible.
7. **Responsive** — check narrow width, long text, overflow, low-motion preferences, dark theme.
8. **Robustness** — test missing/contradictory sources, loading state, invalid inputs and failure path.
9. **Adaptability** — does code use existing project tokens and conventions; can it be reused across domains?
10. **Intellectual property** — independent visual design, links/credit to inspirations, no unlicensed logos/assets.

Reject a demo that marks work as performed without evidence of execution, or presents illustrative numerical values as real-world calculations.
